# Do this next

Implement the Future Feed (`dee9802` is the spec; read ADR
`docs/adr/0024-future-meetings-get-their-own-feed.md` first):

1. `app/feeds.py` — add a builder for `feed-future.xml` ("YXEMinutes —
   Upcoming Meetings"). One entry per Scheduled Meeting, soonest-first,
   no cap beyond the existing 60-day lookahead. Entry content: body +
   date as title, Request-to-Speak Deadline up top, full agenda in
   agenda order with provisional Descriptions. Stable GUID per
   `meeting_id`; update in place on agenda revision.
2. Publish rule: entry appears when the agenda first appears
   (`has_agenda`); fallback — if ~3 days before the deadline and still
   no agenda, publish a bare entry.
3. Drop entries for meetings that have happened (they flip into the
   settled feeds naturally via `build_site.py`'s existing past-meetings
   pipeline).
4. `scripts/build_site.py` — wire it in where scheduled meetings are
   already fetched (~line 377); the data is in hand, feeds must stay
   pure (dicts in, strings out) like the existing two.
5. Tests: `tests/` has feed tests to mirror; run `venv/bin/pytest tests/`
   on a machine with a working venv.
6. Surface the feed: `<link rel="alternate">` in `base.html`, and
   consider mentioning it near the Future tab.
