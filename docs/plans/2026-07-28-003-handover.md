## What landed this session

### Two Atom feeds (`TODO.md` item 12, done)

`app/feeds.py`, written on every build:

- `/feed.xml` — one entry per calendar day the city sat, bodies as
  headings inside it. The default.
- `/feed-items.xml` — one entry per qualifying item.

Both use one gate and differ only in granularity. An item qualifies with
a Description **or** an interpretive chip; qualifying items rank by
`discussion_minutes` and cap at 8 per meeting.

A day publishes once **settled** — every meeting on it has summaries, or
seven days have passed. Stateless: entry ids and `<updated>` come from
the meeting date, so the six-times-a-day deploy produces one entry.

Verified against two meetings pulled live from eSCRIBE with their cached
summaries: 2 day entries, 16 item entries, all five speakers on the
Downtown Entertainment District item named with their organizations.

### The feed does not reuse the card's ranking — ADR `0018`

This is the session's most reusable finding. `extract_meeting_topics`
looked like the right selector and is not. Measured, same substance gate
both sides, top 8 each:

| meeting | what the card's ranking misses |
|---|---|
| 2025-11-25 budget | Capital Options (155.5 min), Housing and Homelessness funding (83.6), Arts, Culture and Events Venues (81.3) |
| 2025-12-03 | Downtown Event and Entertainment District (100.3), Development Incentives Policy (71.1) |
| 2025-12-17 | 6 of 8 agree; misses one 11.0-minute item |

Instead it includes Land Development (3.5), Community Support (10.2) and
a right-of-way dedication (1.4).

Cause is one line, `summarizer.py:96`:

```
duration_score = 0.25 * min(1.0, discussion_minutes(item) / 20.0)
```

Duration saturates at twenty minutes, so a 155-minute debate and a
21-minute one score the same and the tie is broken by dollar signs in the
text and dot-count in the section number. That is `TODO.md` **item 15**.

`extract_meeting_topics` also returns **speaker rows mixed in with items**
— reusing it would have silently returned 6 entries where 8 were asked
for.

### An agenda item has an address (`TODO.md` item 7, done)

`#item-<item_id>` on every card, set as it is drawn, with the page
scrolling after render — a fragment resolved against a skeleton is
dropped, which is what made this look impossible.

The index card links to it too. A row's href carries both parts:
`?t=<ms>` seeks the video, `#item-<id>` places the reader. A consent item
gets the anchor and no seek, so those rows are addressable for the first
time.

Arrival scrolls instantly and twice on purpose — scrolling activates the
sticky player, which changes the height of everything above the target,
so the first jump lands short. A `?t=` click still scrolls smoothly once.

## Traps

- **A browser screenshot cannot verify a JS scroll.** Two Firefox
  screenshots showed the page at the top and both were wrong — the
  capture lands before the scroll. This cost real time and nearly led to
  "fixing" working code. **Use jsdom instead**, it is now proven:
  `npm install jsdom@24` in the scratchpad, `runScripts: 'dangerously'`,
  and stub `IntersectionObserver`, `scrollTo`, `animate` and
  `getBoundingClientRect` in `beforeParse` — jsdom lays nothing out, so
  every rect is top 0 unless you fake one. The probe printed 36 items,
  36 ids, and the exact scroll calls per URL shape.
- **`jsdom@latest` does not run on this Node.** `ERR_REQUIRE_ESM` from
  `html-encoding-sniffer`. Pin `jsdom@24`.
- **`loadMeeting`'s `try/catch` swallows everything** and reports
  "Failed to load meeting details." That is how the jsdom gap presented,
  and it wasted a cycle looking for a page bug. Now `TODO.md` item 16.
- **`_site/` still predates the roster.** Unchanged from `002`. Build a
  preview by fetching live with
  `EscribeMeetingSource(LiveEscribeTransport())` and pulling summaries
  with `git show origin/summaries:summaries/<id>.json`. The two scratch
  scripts that do this are worth rewriting rather than hunting for.
- **`firefox --screenshot` still needs the absolute path first**, never
  `--headless` first, and a preview copied to another directory loses
  its relative `style.css`.
- **Do not measure a ranking by reading it.** Both real findings this
  session — the saturation and the speaker rows in the topic list — came
  from running the real function over real meetings and diffing. Neither
  was visible in the code.
- Everything in `002` still applies: the whole transcript slice matters,
  match speakers by organization, `git commit` fails on an unchanged
  re-save, `deploy.yml` fires on the summarize run **completing** rather
  than succeeding, `summarize_meetings.py` does not load `.env`, the
  judge is noisy, no `gh` and no GitHub token, model is
  `gemini-2.5-flash`.
