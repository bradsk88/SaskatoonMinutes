## Traps

- **`deploy.yml` fires on the summarize run *completing*, not
  succeeding** (`types: [completed]`). It deployed behind a failed run
  this session. Harmless here because the data was good — but a genuinely
  bad summarize run publishes itself the same way.
- **Old code crashes on new data; new code reads old data fine.** Before
  main was pushed, `origin/main`'s `_topic_summary` did
  `(description or "").strip()` — a list is truthy, so `list.strip()`
  raises. Pushing the summaries branch first would have reddened the
  4-hourly deploy cron. **Main first, then summaries. Always.**
- **`--force` is required to re-summarize for a format change**, even
  though `summarize.yml`'s own comment says to leave it off. Every target
  meeting already had a description, so `is_current` returns True and a
  run without `--force` skips all 67 and does nothing.
- **`summarize_meetings.py` does not load `.env`** — `eval_chips.py`
  does (`load_dotenv`), and the asymmetry is easy to miss. A local run
  prints `WARNING: GEMINI_API_KEY is not set` and would go on to produce
  deterministic-only chips. It exits 2 on push access before that
  matters, but do not rely on that ordering.
- **Credits can run out mid-session.** The symptom is
  `429 RESOURCE_EXHAUSTED ... prepayment credits are depleted` and
  `QuotaExhausted`, not a rate limit. Retrying does not help; only Brad
  topping up does. Do not report an eval as passing when it never
  reached the model.
- **Do not conclude the eval passed from one run.** Still true, and the
  two runs this session failed on different items — which is the whole
  argument for running it twice.
- Everything `003` lists still applies: no string-joining continuation
  bullets, the two description rules pull against each other, coverage
  not format is the real ceiling, fresh Firefox profile per screenshot,
  no `gh` installed, model is `gemini-2.5-flash`.
