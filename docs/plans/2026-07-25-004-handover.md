## What happened

The measurement ran and the pre-registered rule was applied.

- **Blind judges: raw 11, clean 9, tie 2** by majority across 22 items.
  Twelve judges, three per item, each given only its own slice of the
  pairs file and forbidden to reason across items. 19 of 22 unanimous;
  34-26-6 across all 66 judgements. Nine items had it 4-2 last time, so
  the direction held and the small-sample defence is gone.
- **Roster attractors: 3 flags clean, 1 raw.** Clean: `Nutana ←
  "Nutanic"` and `Caswell Hill ← "Casual Hill"` (corrections), and
  `Remai Modern ← "Remly"` (fabrication). That gate passed 2-1 and did

- **The raw arm's one flag is the finding.** It produced `Nutana` with no

  its own, which is the job ADR `0004` kept cleanup for.
- **Cleanup deleted.** The prompt, chunking, truncation guard,
  fingerprint, `CleanTranscriptCache`, `LocalDirCache`,
  `_SASKATOON_NAMES`, the clean fixtures, and the three A/B scripts.
  The chip call now reads the raw slice joined exactly as cleanup
  received it, so production matches the arm that was judged.
- **Baseline re-snapshotted from raw** — 111 chips against 118, soft-chip
  coverage 22/24 against 21/24, title echoes 0 against 1. `--check`
  passes. A full eval run is 1m17s and 24 chip calls.

Three fixes followed from reading the output rather than the plan.

- **A public hearing's recorded vote is first reading, not approval.**
  Eight of 24 eval items published "Outcome: Approved" for a motion that
  only put a bylaw in front of council. On 5.1.1 that sat above a
  description reading "City Council denied a rezoning request" — a
  summary contradicting itself. `format_outcome` now reads the motion
  type, and the chip prompt gained a public-hearing guard beside the
  committee one. Baseline re-snapshotted again: 119 chips, 23/24 with a
  substantive soft chip, 0 title echoes.
- **The backfill can be dispatched repeatedly.** The skip rule asked
  whether a summary existed; every meeting had a pre-aggregate one, so
  the run needed `--force`, which turned the skip off and made each
  dispatch redo the last batch. `is_current()` asks what kind of summary
  is cached instead.
- **The workflow defaults to the current term.** With the rule above and
  an empty `--since`, the daily job would have walked backwards through
  the whole archive.

## Do this next

**Watch the daily run, do not dispatch a backfill.** The scheduled job
now covers the term on its own:

- The skip rule asks whether a meeting's summaries are in the current
  format, not whether any exist, so each run walks forward instead of
  redoing the last batch. `--force` turns that off — leave it off.
- Two meetings per tab per run, sixteen tabs, one run a day after
  transcription. Council is the longest pole at 20 in-term meetings, so
  **the term fills in about ten days**.
- `--since` now defaults to `2024-11-01` in the workflow. Without it the
  daily job would keep walking backwards into ~429 pre-term meetings
  that are meant to keep their Legacy summaries.

Measured coverage, on 2026-07-26, against the real cache branches:

- Sampling 10 in-term meetings gave 79 eligible items of 301, about 8 per

## Traps

- **Don't reopen the A/B.** The rule was fixed before the data and it has
  been applied. The harness is gone from the tree by design; it is in
  history if the question genuinely reopens.
- **Never judge an A/B by its labels** — they are re-randomized per item.
  Judge per item, unblind, then aggregate. This has produced confident
  wrong conclusions twice.
- **A blind judge must not read the repo.** Give it one self-contained
  file and forbid the rest, or it finds the key.
- **Split judging by whole items**, ~110k characters per judge. The pairs
  file was 440k at 22 items — too big for one read.
- **The name-density counter in `add_eval_fixture.py` is loose** — it also
  counts `April`, `AM`, `ARO`. Fine for ranking, wrong as a name count.
