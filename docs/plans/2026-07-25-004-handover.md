## Traps

- **Don't reopen the A/B.** The rule was fixed before the data and it has
  been applied. The harness is gone from the tree by design; it is in
  history if the question genuinely reopens.
- **Never judge an A/B by its labels** — they are re-randomized per item.
  Judge per item, unblind, then aggregate. This has produced confident
  wrong conclusions twice.
- **A blind judge must not read the repo.** Give it one self-contained
  file and forbid the rest, or it finds the key.
- **Split judging by whole items**, ~110k characters per judge. The pairs
  file was 440k at 22 items — too big for one read.
- **The name-density counter in `add_eval_fixture.py` is loose** — it also
  counts `April`, `AM`, `ARO`. Fine for ranking, wrong as a name count.
