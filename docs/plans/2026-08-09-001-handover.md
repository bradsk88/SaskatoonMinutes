## The bug

Item timestamps come verbatim from the city clerk's eScribe video
bookmarks (`app/escribe.py`, `_extract_bookmarks`, ~line 263; assigned at
`time_start_ms=bookmark.get("TimeStart")` ~line 327). Clerks sometimes
bookmark an item when it is *called*, immediately before a recess, so the
timestamp lands on dead air and the actual discussion starts minutes
later.

Concrete case: PDCS meeting 2026-08-05 (`72699ed7-c7a1-4687-83fa-b5129afe5b21`),
item 6.3.1 "Downtown BID – Public Realm Bench Removal Request".
Bookmark: 1:33:51 (5631900 ms). Verified against the video: at 1:33:51
the committee goes into recess ("Recessed from 11:01 a.m. to 11:10 a.m."
per the clerk's minutes visible on screen); the presentation actually
starts ~1:44–1:47.

Same meeting, item 6.3.1 of EUCSP 2025-08-05
(`6914c3da-1c32-46a6-ad8b-d78206d9e2e6`) has the same pattern
(bookmark 1:25:15, recess ~1:38–1:46 inside the span).

## Do this next

1. Decide the correction source. We already transcribe meetings with
   faster-whisper (word-level timestamps, `app/transcriber.py`), so the
   cheap rule is: within an item's bookmark span, find "recess" /
   "stand at ease" / "stand down" phrasing in the transcript; if the
   reconvene point is >N seconds (suggest 60) after `time_start_ms`,
   move `time_start_ms` to the first speech after the recess. Only ever
   shift forward; cap the shift (suggest 20 min); log/flag every shift.
2. Find where in the build pipeline transcript data meets agenda items
   (scripts/build_site.py, app/agenda_items.py) and add the adjustment
   there, keeping the raw eScribe bookmark for provenance (e.g. new
   field like `time_start_adjusted` / `adjustment_reason`), rather than
   mutating the scraped value in place.
3. Regenerate the affected meeting(s) and verify 6.3.1 lands at ~1:45.
4. Consider a test fixture from the PDCS 2026-08-05 meeting.

## Traps

- Don't try to detect recesses from bookmark gaps alone: the recess sits
  *inside* the item's span, so there is no gap in the bookmark data.
- `_insert_recesses` only synthesizes recesses from gaps *between*
  bookmarks; it won't catch this.
- Some items legitimately start with brief formalities — don't
  over-shift; that's why the rule should key on explicit recess language.
- Meeting videos are playable segment-by-segment without auth:
  `https://video.isilive.ca/vod/_definst_/mp4:saskatoon/<file>/playlist.m3u8`,
  segments `https://video.isilive.ca/vod/saskatoon/<file>/seg-N-v1-a1.ts`
  (10 s each). Get `<file>` from the player page's `data-file_name`.
  ffmpeg rejects mid-stream single `.ts` frames with PPS errors but the
  first decodable frame still comes out fine.
